# 导入与导出

管理后台的数据页可导入和导出 JSON 备份与浏览器书签 HTML。相关 API 路径见[API 与权限](api.md)。

## 导出

- 导出和预检接口都需要 `format=json` 或 `format=html`；导出不接受 `auto`。
- JSON 导出使用 v2 格式，包含分类树、显式权限、书签字段、标签、置顶状态、归档/删除时间和导出时间。
- HTML 导出使用 Netscape Bookmark 文件格式，保留分类层级、书签标题、URL，以及支持的图标、添加时间和描述。
- Worker 按 300 条一批查询并流式生成文件；浏览器先请求导出预检，再直接下载响应。
- 导出包括管理员可见的私有数据，也包括活动、归档和回收站状态的书签。

HTML 是通用浏览器格式，不表达 Nav 的全部状态：标签、公开/私有权限、置顶、归档和回收站状态不会写入 HTML。需要完整迁移时使用 JSON。备份可能包含私有书签，应按敏感数据保管。

## 导入

导入接口通过 `format=json`、`format=html` 或 `format=auto` 选择格式，`strategy` 可选且默认为 `skip`。接口接受 JSON 或 Netscape Bookmark HTML，单个请求正文上限为 10 MB。JSON 需要包含 `bookmarks` 数组；当前支持 v2、v1 和未带版本号的扁平书签备份。缺失版本号按 v1 处理。早期以嵌套分类树表示、在分类节点内嵌 `children` 或 `bookmarks` 的旧 JSON 结构已不支持。

JSON v2 的分类通过 `slug` 和 `parentSlug` 表示层级；书签通过 `categorySlug` 指向分类。v2 引用不存在的分类会报错。导入中已存在的分类按 slug 匹配，并保留目标库中已有分类的层级和权限；不会用备份覆盖已有分类设置。

导入参数 `strategy` 接受 `skip`、`create` 和 `update`，默认 `skip`。所有策略都会创建目标库中不存在的书签；遇到规范化 URL 已存在的记录时，只有 `update` 会更新现有记录，`skip` 与 `create` 会跳过。更新以 URL 匹配，不替换已存在书签的 URL。

旧备份或 HTML 缺少权限信息时，新书签按私有导入。更新记录时，如果备份未声明权限，系统会保留现有权限；如果新分类关系会移除既有私有保护，则会显式保留为私有。
