# 导入与导出

管理后台的数据页可导入和导出 JSON 备份与浏览器书签 HTML。相关 API 路径见[API 与权限](api.md)。

## 导出

- 导出和预检接口都需要 `format=json` 或 `format=html`；导出不接受 `auto`。
- JSON 导出使用 v2 格式，包含分类树、显式权限、书签字段、标签、置顶状态、归档/删除时间和导出时间。
- HTML 导出使用 Netscape Bookmark 文件格式，保留分类层级、书签标题、URL，以及支持的图标、添加时间和描述。
- Worker 按 300 条一批查询并流式生成文件；浏览器先请求导出预检，再直接下载响应。
- 导出包括管理员可见的私有数据，也包括活动、归档和回收站状态的书签。

下载中途发生数据库查询或网络错误时，响应流会失败，文件可能不完整；重新导出后再使用文件。预检仅确认开始下载前的数据库可读性，不保证后续所有分页查询成功。

HTML 是通用浏览器格式，不表达 Nav 的全部状态：标签、公开/私有权限、置顶、归档和回收站状态不会写入 HTML。需要完整迁移时使用 JSON。备份可能包含私有书签，应按敏感数据保管。

## 导入

导入接口通过 `format=json`、`format=html` 或 `format=auto` 选择格式，`strategy` 可选且默认为 `skip`。接口接受 JSON 或 Netscape Bookmark HTML，单个请求正文上限为 10 MiB（10 × 1024 × 1024 字节）。Worker 按实际读取字节累计大小，超限立即取消正文流并返回 413，不依赖 `Content-Length`。

JSON 需要包含 `bookmarks` 数组；当前支持 v2、v1 和未带版本号的扁平书签备份。缺失版本号按 v1 处理。早期以嵌套分类树表示、在分类节点内嵌 `children` 或 `bookmarks` 的旧 JSON 结构已不支持。缺少 URL 的书签、缺少名称的分类和非对象条目会被忽略；没有有效书签且存在此类错误时返回解析错误。导入器对有效条目继续处理，不把这种忽略记入结果中的 `errors`。

JSON v2 的分类通过 `slug` 和 `parentSlug` 表示层级；书签通过 `categorySlug` 指向分类。引用可指向本次备份或目标库已有分类。导入器在任何写入前检查全部 v2 分类引用、书签分类引用和分类循环；校验失败返回 400，不创建分类或书签。v1 缺失的分类引用按未分类处理，缺失的父分类按根分类处理。导入中已存在的分类按 slug 匹配，并保留目标库中已有分类的层级和权限；不会用备份覆盖已有分类设置。

导入参数 `strategy` 接受 `skip`、`create` 和 `update`，默认 `skip`。所有策略都会创建目标库中不存在的书签；遇到匹配记录时，只有 `update` 会更新，`skip` 与 `create` 会跳过。匹配规则如下：

- 未删除书签（包括归档）只匹配目标库中未删除的规范化 URL。回收站里同 URL 的旧记录不阻止创建新书签；`update` 也不会把旧记录当作未删除书签更新。同一次导入中的未删除重复 URL 采用第一条，后续条目跳过。
- 回收站书签按规范化 URL、`addedAt`、`deletedAt` 匹配，匹配一次消耗目标库中的一条记录。即使多个记录在同一秒创建、删除，也会保留备份中的记录数量。先为包含 `addedAt` 的条目预留精确匹配，再为缺少 `addedAt` 的旧条目按规范化 URL 和 `deletedAt` 逐条匹配，避免混合备份重复导入时新增历史记录。
- 回收站记录只与回收站匹配，不覆盖同 URL 的未删除记录。重复导入同一完整 JSON 备份不会新增已经匹配的记录；目标库已有数量少于备份时只补缺少的条目。相同回收站身份有多条记录时，匹配不区分标题等内容，`skip` 保留目标库内容；`update` 更新匹配到的记录，保留记录数量。

更新不会替换已有书签的 URL 和添加时间。新增书签使用备份的添加时间，缺失时使用数据库当前时间。完整恢复到空库时，JSON 可保留各状态及同 URL 的删除历史；导入已有库属于按上述规则合并，不会删除目标库中额外的数据。

通过引用校验后，分类、书签和标签按批次写入，不是整个文件的一次原子事务。数据库故障返回 500，已经成功的批次可能保留。先查看数据，再用原备份和 `skip` 重试可补齐缺失记录；如需修复已创建书签缺失的标签或字段，使用 `update`，注意它也会覆盖匹配记录的备份字段。

管理页面采用 `skip`（跳过重复）。读取、上传或处理期间锁定文件选择与拖放；取消上传后恢复操作。处理阶段的“停止等待”只终止浏览器等待，服务端可能继续导入，可稍后查看书签。停止等待不会撤销已经导入的数据。

旧备份或 HTML 缺少权限信息时，新书签按私有导入。更新记录时，如果备份未声明权限，系统会保留现有权限；如果新分类关系会移除既有私有保护，则会显式保留为私有。

## JSON v2 示例

分类和书签都可以没有数据；`categories` 可省略，`bookmarks` 必须是数组。以下示例展示字段与层级关系；导出文件会为可空字段写入 `null`：

```json
{
  "version": 2,
  "exportedAt": "2026-10-14T00:00:00.000Z",
  "categories": [
    { "name": "开发", "slug": "dev", "parentSlug": null, "icon": null, "visibility": "public" },
    { "name": "文档", "slug": "docs", "parentSlug": "dev", "icon": null, "visibility": "private" }
  ],
  "bookmarks": [
    {
      "title": "Cloudflare Docs",
      "url": "https://developers.cloudflare.com/",
      "description": "Cloudflare 开发文档",
      "iconUrl": null,
      "visibility": "public",
      "categorySlug": "docs",
      "tags": ["Cloudflare"],
      "isPinned": true,
      "addedAt": "2026-10-01T08:00:00.000Z",
      "archivedAt": null,
      "deletedAt": null
    }
  ]
}
```

时间字段使用导出文件中的原值。书签的显式权限为公开但祖先分类为私有时，有效权限仍为私有，详见[权限继承](architecture.md#权限继承)。

## HTML 兼容边界

HTML 导入按文件遍历顺序为每个文件夹生成独立 slug。同名文件夹即使位于同一父级，也依次使用 `name`、`name-2` 等可用 slug，保留各自层级与书签归属；slug 最长 64 字符，无法从名称生成 slug 时使用 `folder`。相同文件的重复导入会生成相同 slug，仍按已有分类 slug 合并，不覆盖目标分类的层级或权限。调整文件夹顺序可能改变同名文件夹的后缀，因此完整迁移优先使用 JSON。

名称为“未分类”或规范化为 `uncategorized` 的文件夹是保留入口，本身不创建分类，其书签归入最近的非保留祖先分类；没有该祖先时为未分类。解析器按行读取 Netscape 格式的 `H3`、`A`、`DD` 与 `DL` 标记，不保证兼容任意压缩为单行的 HTML 或浏览器私有扩展。
