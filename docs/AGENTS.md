# 文档维护

项目使用说明、当前行为、架构、数据库、API、部署流程和必要取舍统一维护在 `docs/`。根目录 `README.md` 只保留项目简介和文档入口。

- 按根目录 [AGENTS.md](../AGENTS.md) 的任务路由读取和维护命中的主题文档；[文档索引](index.md) 用于查找入口，无需通读所有文档。
- 根 AGENTS.md 保留项目约束、任务路由、自主权和验证契约；主题细节写入对应文档，不在入口重复展开。
- 服务边界、权限继承与分页取舍归 architecture.md；表结构、索引、触发器与迁移维护规则归 database.md；部署和远程迁移的执行流程归 deployment.md。
- 新增、移动或删除主题文档时，同步根任务路由、文档索引和受影响的交叉链接；维护规则变化时同步本文件。
- 描述已经实现的行为，以源码、配置、迁移和自动化流程为准；不要把计划或未验证的结论写成当前行为。
- 功能、入口位置、页面交互与文案、API、数据结构、权限、导入导出或部署流程变化时，更新对应主题文档及受影响的链接。
- 页面交互说明应包含失败后的恢复入口；区分取消上传、停止等待与服务端写入结果。
- 侧栏、操作菜单和选择浮层的变更应同步入口层级、桌面/移动端展开方向与关闭后的焦点恢复；区分首次加载失败、刷新失败保留的数据与操作失败保留的草稿。
- 固定栏、实时信息和动效变化应说明移动端显隐、时间来源与更新方式，以及减少动态偏好的行为。
- 保留明确的兼容边界和行为取舍；删除过时说明，不维护与实际行为脱节的待办清单。
