# Web 视觉：私人书签柜

产品：一个人每天打开的书签柜。不是公开导航、不是 SaaS 后台。

## Token

| 角色         | 浅色      | 深色      |
| ------------ | --------- | --------- |
| 纸面 paper   | `#f5f5f7` | `#1d1d1f` |
| 墨 ink       | `#1d1d1f` | `#f5f5f7` |
| 淡墨 muted   | `#6e6e73` | `#a1a1a6` |
| 线 rule      | `#d2d2d7` | `#3a3a3c` |
| 青釉 seal    | `#1c6b5a` | `#7bd3b7` |
| 侧栏 sidebar | `#f0f0f2` | `#242426` |

字体：正文与标题使用 `Geist`，网址与计数使用 `Geist Mono`。

## 布局

```
┌ login ─────────────────────┐     ┌ header: 标识 + 添加 + 菜单 ─────────┐
│           印               │     │  ╭─ 浮动索引 ─╮  搜索               │
│          书签柜             │     │  │ 导航、标签  │  书签卡片             │
│        [密码] [进入]        │     │  ╰───────────╯  归档 / 回收站       │
└────────────────────────────┘     └─────────────────────────────────────┘
```

签名：淡灰纸面上的浮动圆角索引栏，让书签卡片像触手可及的应用条目。用一处青釉色标识当前选择与主动作，其余层级由留白、圆角和低对比线条建立。卡片是实体点击面，不是玻璃拟态。

### 侧边栏（响应式）

同一份标签索引，两种归宿：

- `lg`（≥1024px）及以上：索引栏以独立圆角浮层常驻左侧，按常用入口、归档、回收站和标签分组。
- `lg` 以下：索引栏收进抽屉，从顶栏按钮唤起，选完标签自动收起。

### 标签操作

- 标签只在索引栏内以列表呈现，不在内容区重复做横向标签胶囊。标签区提供即时搜索、计数和空结果提示；点击条目直接进入对应标签视图。
- 书签卡片上的标签仍可点击筛选，但只作为卡片内的轻量信息，不承担主导航。
- 活动书签的整张卡片都是新标签页跳转的命中区域；置顶、归档、编辑、删除及标签保持为独立可点击控件。
- 添加/编辑书签时，标签以已选胶囊呈现；输入后按回车确认，也可以从已有标签建议中点选。保存时仍按现有 API 的 `string[]` 契约提交。

## 组件组合

界面不手写临时 markup，一律从项目内本地化的 shadcn/base-nova 组件（`src/web/components/ui`）组合：

- 骨架与导航：Sidebar 系（侧边栏索引、导航结构），配合 AppShell 工作台壳。
- 覆盖层：Dialog、AlertDialog；覆盖层必须带标题，视觉隐藏用 `sr-only`。
- 内容块：优先使用现有 Card 系；简单空状态和加载占位可保持功能内局部结构，不为一次性布局新增组件文件。
- 表单：Field 组合（Field + FieldLabel + Input / Select / Textarea / Checkbox），校验用 `data-invalid` + `aria-invalid`。
- 反馈与点缀：优先使用已安装的 toast、Badge、Separator、DropdownMenu 等，不保留未使用的 UI 文件。
- 图标只用 lucide-react，按钮内图标走 `data-icon`，不写尺寸类。

以上是组合惯例：具体以 `src/web/components/ui` 中已安装的组件为准，缺的组件按需补装进同一目录，而不是手写自定义结构替代。配色只走语义 token（paper/ink/rule 落到 background/foreground/border，seal/rust 落到 primary 等），组件不写死 hex，也不做手写 `dark:` 覆盖。

## 不做什么

不套奶油底+衬线模板的大数字 hero；不套黑底酸绿；扩展页面不套这套皮肤。
