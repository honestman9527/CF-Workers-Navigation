# 使用与本地开发

## 产品页面

`/` 直接打开统一的书签柜导航首页。采用 [Apple 设计规范](../DESIGN.md) 中的系统字体、白灰底色、蓝色强调与轻量分隔，保留亮色、暗色、跟随系统和背景图片设置。浏览器禁止本地存储时，主题切换仍在本次页面会话中生效，重新打开页面后可能恢复默认值。

公开设置首次加载失败时，搜索区上方显示错误与「重试设置」，保留导航内容及搜索输入，并暂用默认搜索引擎；重试过程中显示加载状态且不重复请求。已有设置刷新失败时继续使用上次成功的值，后台保存成功后同步更新前台。

### 通用交互约定

首次加载失败显示具体错误与原地重试入口；刷新失败保留已有数据，操作失败保留编辑草稿。加载或提交期间禁用重复操作，提供可感知的进度文案；操作成功后移除相应错误。同一书签正在写入时，冲突操作提示「该书签正在处理中，请稍后重试」；保存冲突在编辑器内显示并保留草稿，待原操作完成后可重试。弹出菜单关闭后恢复触发点焦点，分类筛选与移动浮层的关闭行为见[管理后台](#管理后台)。

### 分类浏览与轻管理

首页依次显示页头、搜索区、常用网站、吸顶分类导航和连续分类分区。顶部一级分类导航横向滚动，点击只定位分区，保留该分区此前选择的子分类；选中深层分类时高亮所属一级分类。一级分类按现有顺序排列，默认包含全部后代网站；未分类单独显示。网站条目只显示图标、名称与一行描述，缺少描述时显示域名。

分区内直接显示当前节点的下一层分类入口，进入子分类后用“开发 → 前端 → React”这样的完整路径表示位置；点击祖先回到该层并汇总它及全部后代网站，点击路径中的一级分类查看该分区全部内容。叶子节点只显示路径。入口默认最多两行，超过时提供“更多分类”和“收起”；手机、平板、桌面采用相同交互。路径可换行，长入口名称截断并保留完整标题；切换分类后焦点留在当前路径。

常用和每个分类首批加载 12 项，点击「展开更多」原地追加 24 项。分类接近可视区域时加载，各一级分区独立保留选择，各个已访问分类在本次页面浏览中缓存网站、游标及错误；返回该分类时恢复已追加内容。首批失败可原地重试，追加失败保留已有项目并重试当前游标；切换分类取消未完成请求，迟到响应不写入当前内容或缓存。新增或编辑书签后刷新内容缓存，仍有效的分类路径保留。缓存只存在于页面内存，离开页面或身份变化时清除。

登录后，页头提供添加书签，条目提供编辑和加入/取消常用；归档、删除、分类和标签整理进入后台。常用操作只刷新常用分区并更新当前条目，期间禁用当前书签的常用按钮；添加或编辑后刷新各分区及分类、标签。登录、退出或服务端明确确认会话失效时，立即卸载原身份的列表、索引与编辑草稿并取消请求，避免私有数据残留。焦点恢复或定时认证检查遇到网络故障、服务端临时错误时保留已确认身份、列表与草稿；连接恢复后继续检查。

### 搜索与链接兼容

搜索明确分为「站内」和「网页」。首次默认站内，随后记住当前浏览器最后使用的模式，链接显式指定的 `mode=site|web` 优先；切换保留输入。站内关键词与单个标签或无标签可组合，标签入口收进「筛选」。结果替换导航内容区；清除关键词和筛选后恢复分类位置及已加载内容。站内模式输入网址不会触发网页跳转。

网页模式提供引擎选择、bang 搜索与网址直达；只有 bang 前缀而没有关键词时禁用提交。链接指定的引擎不可用时保留该选择并要求重选，不静默改用其他引擎。`/` 聚焦搜索，上下键选择站内结果、回车打开，Escape 清除搜索。中文输入法组合期间不执行快捷操作或提交。

URL 使用 `mode`、`q`、`engine`、`category`、`tag`、`untagged`。单个 `category` 记录当前操作的分类；刷新或分享链接恢复它的完整路径并定位所属一级分区，其他分区从一级开始。本次页面浏览中，历史条目在内存保存各分区选择和滚动快照；前进、后退结合分类内容缓存恢复当时视图，不重复跳转分类锚点。站内搜索使用关键词和标签条件，不将浏览分类混入搜索。`tag` 优先于 `untagged`；清除搜索保留浏览分类。`/launch` 重定向到首页网页模式，`/workspace` 重定向到首页站内模式；保留有效查询、引擎、分类和标签参数，丢弃旧页码、游标和布局参数。浏览器前进/后退恢复 URL 中的模式、查询与筛选，不再读取双入口偏好。

### 管理后台

`/admin` 提供概览、书签、分类、标签、设置和导入导出。桌面使用管理侧栏、顶部工具栏及书签表格，手机使用抽屉和紧凑书签行。书签提供状态、分类、标签、常用与关键词筛选，默认每页 20 条，可选 10/20/50/100 条。添加与编辑使用弹窗，归档、删除、永久删除、分类删除和标签合并等保留确认步骤。

桌面侧栏可完全收起，展开偏好保存在当前浏览器；底部返回入口始终到统一首页。更多菜单提供亮色、暗色、跟随系统及退出登录；桌面向右打开，手机向上打开。切换主题保留移动抽屉，返回前台关闭抽屉，收起侧栏后仍监听系统主题。退出期间禁止重复操作，失败提示后可重试。后台各页面共用布局中的消息提示，切换管理页面后仍可显示操作结果。

分类树初次只显示一级分类，可逐层展开；新建子分类展开父分类，刷新保留展开状态。每行保留新建子分类、重命名及更多入口；更多菜单提供排序、访问权限、移动和删除。移动使用独立树形浮层，排除自身和后代，提示权限继承变化。分类筛选与移动浮层支持外部点击及 Escape 关闭，键盘关闭或选择后恢复焦点，窄屏自动定位并可滚动。标签使用列表管理；合并失败保留目标选择，没有其他目标时禁用合并。

首次加载失败显示错误与重试入口；分类、标签及概览刷新失败保留原数据和编辑草稿。书签管理页的分类、标签索引各自显示加载状态、错误与重试；首次读取中禁用对应筛选，刷新失败仍保留已有筛选项，重试期间不重复发起读取。新建、重命名和保存失败保留输入。设置继续提供隐私默认值、背景图、图标来源和网页搜索引擎；导入导出格式及取消语义见[导入与导出](import-export.md)。

前后台复用书签编辑状态与提交规则，分别提供定制前台外观和后台组件外观。保存期间禁用编辑与关闭，避免重复提交；网址变化或编辑器卸载取消元数据和图标补全，迟到结果不写入新草稿或继续发起保存。“自动填写”只补充空白标题、描述和图标，部分获取失败提示手动补充。“自定义图标”默认折叠，不清空既有值。标签支持回车和英文逗号确认，直接保存归并草稿并去重。中文输入法组合期间不提前确认标签或重命名。

访客只能读取公开且处于活动状态的内容。管理员可管理私有内容。权限继承、内容移动和删除分类的规则见[架构与服务边界](architecture.md)及[API 与权限](api.md)。

### 视觉确认

验证标准见根 [AGENTS.md](../AGENTS.md#风险匹配验证)，视觉基线见 [DESIGN.md](../DESIGN.md#本项目组件与状态规则)。人工检查覆盖手机、平板、桌面、亮暗主题、背景图、长文本，以及加载、错误和操作反馈状态。

## 本地启动

要求 Node.js `>=24`、pnpm `>=11`。

```powershell
pnpm install
Copy-Item .dev.vars.example .dev.vars
```

Bash 中对应的初始化命令为：

```bash
pnpm install
cp .dev.vars.example .dev.vars
```

编辑 `.dev.vars`，为 `ADMIN_PASSWORD` 和 `SESSION_SECRET` 设置仅供本地使用的值。然后初始化本地 D1 并启动：

```powershell
pnpm db:migrate:local
pnpm dev
```

打开 `http://localhost:8787`。`pnpm dev` 会先构建 Web，确保 Worker 的静态资源目录已就绪，再并行启动 `dev:worker` 和 `dev:web`；任一进程退出时结束另一进程。`dev:web` 通过 `pnpm run build --watch` 复用构建配置，修改 Web 源码后重新构建。

## 常用命令

```bash
pnpm dev                 # 启动本地 Worker 与 Web 构建监听
pnpm dev:web             # 单独监听并重新构建 Web
pnpm dev:worker          # 单独启动 Worker，需要已有 Web 构建产物
pnpm build               # 构建 Web 到 dist/web
pnpm cf:typegen          # 按 Wrangler 配置生成 Worker 绑定声明
pnpm cf:types:check      # 检查 Worker 绑定声明与 Wrangler 配置一致
pnpm lint                # 静态检查
pnpm fmt:check           # 格式检查
pnpm typecheck           # 检查 shared、Worker、Web 与 Worker 测试，最多两项并行
pnpm test                # 运行单元测试和 Worker 集成测试
pnpm check               # 依次运行格式、lint、类型和测试检查
pnpm db:migrate:local    # 应用本地 D1 迁移
pnpm db:migrate:remote   # 应用远程 D1 迁移
pnpm run deploy          # 构建 Web 并部署 Worker
```

`pnpm check` 按格式、lint、类型检查、测试四阶段顺序执行；类型检查覆盖 shared、Worker、Web 和 Worker 测试，最多两项并行，任一失败时终止其他类型检查并停止排队任务。`pnpm test` 依次运行单元测试和 Worker 集成测试。原 `cf-typegen`、`watch:web` 命令已分别改名为 `cf:typegen`、`dev:web`。

`pnpm cf:typegen` 将配置中的 D1、限流及其他绑定生成到 `src/worker/bindings.d.ts`；Worker 运行时类型继续来自 `@cloudflare/workers-types`，避免两套运行时声明重复。修改 Wrangler 绑定配置后重新生成，并运行 `pnpm cf:types:check` 检查声明是否与配置同步。

数据库结构与迁移维护规则见[数据库与迁移](database.md)。部署使用 `pnpm run deploy` 显式调用项目脚本，避免命中 pnpm 内置的 `deploy` 命令；该脚本不负责应用数据库迁移，生产部署前的迁移与密钥步骤见[部署](deployment.md)。

## 目录结构

```text
src/
├── worker/       # Hono 路由、D1 服务、Drizzle schema 与备份格式
├── web/          # React Web 前端
└── shared/       # Web 与 Worker 共用的 API 和偏好契约
public/           # Web 静态资源
migrations/       # D1 基线和递增迁移
test/
├── unit/         # shared 与 Web 单元测试
└── worker/       # Cloudflare Worker 集成测试
```

这是单包仓库。根 `package.json` 管理依赖与命令；`pnpm-workspace.yaml` 配置 pnpm 安装脚本策略。Worker 和 Web 使用同一份部署配置。
