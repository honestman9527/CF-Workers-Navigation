# 架构与服务边界

## 运行时与代码边界

项目由 Cloudflare Worker、D1 和 React Web 组成，Web 构建产物输出到 `dist/web`。`wrangler.jsonc` 将该目录配置为静态资源，并启用单页应用回退；`/api`、`/api/*` 和 `/health` 先进入 Worker，其余静态资源由 Cloudflare 静态资源路由提供。Worker 不再手动回退或读取前端静态文件。

`src/worker/index.ts` 导出 Hono 应用。路由负责 HTTP 参数验证和响应，`src/worker/services/` 负责业务规则与 D1 访问，`src/worker/transfer/` 负责备份格式。跨端 DTO、端点和 API 客户端位于 `src/shared/`。Web 按功能组织在 `src/web/features/`，前台位于 `features/navigation/`，后台位于 `features/admin/`。书签编辑状态与提交规则提取到 `useBookmarkEditor`，前后台共用逻辑、独立呈现；组件技术约束见根 [AGENTS.md](../AGENTS.md)，视觉规范见 [DESIGN.md](../DESIGN.md)。

Worker、Web、shared 分别使用独立的 TypeScript 配置，隔离 Cloudflare Worker、浏览器和共享代码的运行时类型。测试统一放在 `test/`，分为 `unit/` 和 `worker/`。

书签编辑与备份导入通过 `src/worker/services/bookmark-tags.ts` 的 `withBookmarkTagWrites` 共用标签替换规则。该 module 的 interface 是一个有作用域的回调：调用者按顺序提交已经写入的书签及目标标签，implementation 负责跨批缓冲、D1 参数分块和退出收尾，导入流程无需了解标签批次容量。普通编辑使用单次替换，导入在新增和更新阶段各使用一个作用域，维持原有跨书签批次聚合。D1 继续作为现有 adapter；[标签关联](../GLOSSARY.md)的规则与验证集中在同一 seam，以获得 locality 和两类调用者共用的 leverage。失败与部分写入规则见[导入与导出](import-export.md#导入)。

Wrangler 配置中的绑定声明生成到 `src/worker/bindings.d.ts`；密钥声明单独维护在 `env.d.ts`。生成与一致性检查命令见[使用与本地开发](usage.md#常用命令)。

Web 构建自动生成静态资源 `_headers`：CSP 仅允许本站脚本，并按最终 HTML 计算内联主题初始化脚本的 SHA-256；自定义图标和背景图片允许 HTTP、HTTPS 与 data 图片，动态样式保留内联支持。静态页面禁止嵌入框架、设置 `nosniff` 与 `no-referrer`；API 响应头契约见 [API 与权限](api.md#基础规则)。带内容哈希的 `/assets/*` 使用一年 immutable 浏览器缓存，HTML 继续按平台默认规则重新验证。

表结构、索引、触发器与迁移维护规则见[数据库与迁移](database.md)。

## 权限继承

每个分类和书签都有显式 `public` 或 `private` 权限。有效权限按当前分类祖先链计算：书签自身为私有，或所在分类及任一祖先为私有时，书签有效权限为私有。祖先私有不能被后代或书签的显式公开设置覆盖。

新建分类和书签默认遵循设置中的默认权限；全新安装的默认值为公开。数据库字段与升级时的默认值见[数据库与迁移](database.md#数据模型)，导入权限默认值与兼容行为见[导入与导出](import-export.md#导入)。访客看不到私有内容、私有分类和私有内容产生的计数或标签。

移动书签或分类会按新分类路径重新计算有效权限。显式公开的内容如果移出私有分类，可能会对访客公开；将私有分类改为公开也可能公开显式公开的后代内容。显式设为私有的后代仍保持私有；管理界面对移动操作有提示。删除分类时，直接书签变为未分类、子分类上移到被删分类的父级，并把原先依赖被删私有路径的内容显式设为私有，避免因删除而公开。

## 分页与查询行为

前台分类浏览与站内搜索采用游标分页，后台表格采用页码分页：连续加载避免每页计算总数，后台精确总数支持页码导航。分类各层级复用同一聚合查询；页面批量大小、层级入口与加载交互见[使用与本地开发](usage.md#分类浏览与轻管理)，排序及请求/响应契约见 [API 与权限](api.md#书签列表与搜索参数)。

各一级分区使用独立游标资源，按已访问分类缓存项目、下一页游标和错误。切换分类取消旧请求并阻止迟到响应写入缓存。书签新增、编辑通过版本失效清除旧内容缓存并刷新索引；常用切换只刷新常用资源并覆盖对应条目状态。缓存仅属于当前身份和页面挂载，不写入持久存储。站内搜索使用独立游标资源，隐藏但不卸载浏览分区。

前后台通过 `useBookmarkMutations` 共用书签保存、常用切换和状态变更命令，以及重复提交保护、成败传播和关联索引刷新规则。调用者收到已提交的书签变更后，分别执行前台游标缓存覆盖或后台页码刷新，无需传入任意写入函数或选择是否刷新关联索引；常用变更自动跳过分类和标签刷新。保存失败传播给编辑器以保留草稿，其余失败由各自呈现反馈。页面卸载后停止旧内容与索引刷新；完成反馈继续交由呈现处理，前台忽略旧页面提示，后台共享提示可跨管理页面保留。确认对话框和成功文案属于后台呈现，共享写入 module 不依赖 Toast 或任何外观。

页码模式需要额外计数查询；计数只连接筛选必需的表，不做列表投影中的标签聚合，以避免重复处理标签关联。

列表、搜索和导出都先在物化 CTE 中执行权限过滤、排序与分页，再为该页聚合标签和分类，避免先对全部匹配书签展开标签关联。游标模式多取一条以判断后续页面；页码模式的独立计数保留完整筛选条件。该实现限制了关联聚合的数据量，实际 D1 耗时和读取费用仍需按生产数据量观测。

## 页面路由与身份边界

`/` 为统一首页，URL 的 `mode=site|web` 隔离两种搜索行为。URL 的单个 `category` 定位当前分类，其他分区选择仅存在于页面内存；刷新按链接重新初始化。首页从同一份 Router location 读取分类和历史条目标识，避免导航期间新旧状态混用。页内历史快照按条目标识保存分区选择和滚动位置，历史切换在分类缓存呈现后恢复滚动；首页自行处理滚动，其他路由继续由 Router 恢复，避免重复定位覆盖历史位置。旧 `/launch`、`/workspace` 仅负责参数映射与替换重定向，分别进入网页、站内模式；旧分页、布局及双入口偏好停用。模式和筛选的具体规则见[使用与本地开发](usage.md#搜索与链接兼容)。

分类浏览历史 module 由 `useCategoryBrowse` 统一读取 Router location，解析查询与模式偏好，记录导航前的快照，并在分类选择、分区定位和历史切换时协调滚动与焦点。页面通过 `update`、`selectCategory` 和 `locateSection` 表达浏览意图，无需调用快照记录或拼接 DOM 定位标识。分区呈现和浏览命令共用分区标识；独立的游标内容缓存仍由 `useBookmarkFeed` 管理。

认证状态切换会重建 RouterProvider 及导航页，卸载原身份的列表、分类、标签与编辑状态，并使全局 API 请求失效。服务端独立验证每次请求的权限，认证协议见 [API 与权限](api.md#基础规则)；会话检查失败时的页面恢复行为见[使用与本地开发](usage.md#分类浏览与轻管理)。

公开设置按 Jotai store 合并正在进行的请求；已保存设置会使较早的读取结果失效。公开设置可缓存复用，私有内容不进入 localStorage。存储失败时主题偏好回退到页面内存；重试入口与可见行为见[使用与本地开发](usage.md#产品页面)。
